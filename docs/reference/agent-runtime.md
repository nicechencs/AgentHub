# Agent 协作运行环境参考

本页说明协作时如何选择能力等级、核实运行环境和处理能力缺口。它记录可复核的当前观察，不承诺未验证的自动调度、模型切换或跨工具接入。项目红线见 [AGENTS.md](../../AGENTS.md)，验证入口见[测试与验证](../guides/testing-and-validation.md)。

## 能力等级

能力等级描述任务所需的推理与判断强度，不是 Agent 名称、权限或安装状态：

| 等级 | 适合工作 |
| --- | --- |
| `T1` | 机械执行、定向读取、格式整理和有明确步骤的低风险修改 |
| `T2` | 默认工程任务：局部实现、测试、普通错误路径和单模块判断 |
| `T3` | 深推理：跨文件契约、复杂状态流、并发、数据一致性和反方复核 |
| `T4` | 异常推理：基础假设可能错误、多方案需要深取舍、多次有证据尝试仍解释不了，或需要判断跨系统正确性 |

风险不等于难度，并发数量不等于模型数量。发版或数据写入可能推理简单但风险很高；一处竞态可能改动很小但需要 `T3`。普通跨层、迁移或安全工作按实际推理难度从 `T2` 或 `T3` 开始，并用更严格的风险验证补足后果控制；它们不会因为主题名称自动升级为 `T4`。满足可靠要求的最低等级就是目标等级；文件数量、耗时、测试数量或参与 Agent 数量不会自动升级等级。可以直接从预计需要的等级开始，不要求先用低等级失败。升级时记录卡住的具体推理问题、证据缺口或后果，而不是只写“需要更强模型”。关键判断完成后，明确的实现、整理或验证可以回到 `T2`/`T3`。

角色与等级独立：计划者、实现者、审查者可以由不同等级承担；同一 Agent 可承担多个阶段，但实现者自查不构成独立审查。

## 运行环境核实

只有在相关能力将被使用、配置将被改变，或已有证据显示环境状态可能影响结论时，才核实对应运行环境；不要求每个任务探测所有权限、所有模型、付费能力或写入入口。核实只依据当前运行器能实际报告的事实：

1. 对将要使用的 Agent、模型或运行器，分别记录工具宣告支持、配置文件存在和实际运行成功；三者不能互相替代。实际标识未知时记录“未知”，不虚构统一的 `registered` 能力结构或固定查询接口。
2. 核对仓库版本、工作区状态、依赖和目标文件；把环境输出与源码、测试结果分开记录。
3. 只对本任务涉及的模型选择、并发、子 Agent、工具启动和写入能力做小范围验证；配置文件存在不代表运行时已加载。
4. 任务结束时记录实际使用的 Agent/模型、失败项、降级路径和未验证能力。

本项目未约定跨 Agent 的统一能力查询接口。本页不假定某个固定工具名、字段名或命令列表。若运行器提供能力列表，使用其当前接口；若不提供，不要自行补造统一 schema，可用可执行入口、帮助输出或一次无副作用的最小调用作为对应证据。无法确认时写“未验证”，不要把目录、示例或配置推断成生效能力。

## 模型名称与本机观察

原协作提示词中的映射 `T1 luna`、`T2 terra`、`T3 sol`、`T4 astra` 只能作为记录示例；它不是 AgentHub 的配置，也不要求任何运行器支持这些名称。模型绑定必须使用当前运行器实际注册的标识，不能把示例名、裸模型名或旧会话授权写成当前能力。

截至 2026-09-08，本机观察到：仓库内 `.codex/config.toml` 位于被 Git 忽略的目录，内容包含启用 Agent、并发上限 `8`，以及未固定模型时的 `gpt-5.6-luna` / `xhigh` 默认值。这只是本机文件观察，不是运行效果验证，也不代表其他 Agent 读取它。`.grok` 下有被忽略的 workflow 示例；它不能证明 Grok 已注册、可执行或会被当前任务加载。仓库没有 `.pi` 目录；这不能证明 Pi 不可用，只能说明本仓库没有可供本地核对的目录证据。

不要把上述观察写成“自动切换已完成”。只有实际调用、运行日志或可重复的最小验证，才能说明配置已加载、模型可执行或并发限制生效；敏感配置和登录信息不得写入交接或报告。

## 能力缺口处理

遇到工具能力不足时按以下路径处理：

- 没有子 Agent：由主 Agent 串行完成可安全完成的工作；需要独立审查时明确缺口并降低结论范围。
- 模型不可选或未注册：记录实际标识和失败原因，选择已核实且能力足够的替代；不要伪造指定模型完成。
- 工具未加载、启动失败或权限不足：先核对入口、版本、沙箱和失败输出；能做的只读调查继续，不能把环境错误归因于代码或用更强模型绕过。
- 未加载根 `AGENTS.md` 或必需文档：先补读并重新评估已做判断；无法补读时停止依赖该规则的写入或审查，并报告缺口。
- 运行器不支持并发、固定版本或独立工作区：改为串行、明确基线和 dirty 状态，保留同等验收证据；不能声称完成了隔离执行。

环境限制不自动升级为产品缺陷。交付时区分“代码已验证”“环境限制下未验证”和“工具执行失败”，并说明对结论的影响。
