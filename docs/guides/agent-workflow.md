# Agent 协作指南

任务分级与工程红线见 [AGENTS.md](../../AGENTS.md#协作)。本页只规定分工、交接和验收的操作。

## 委派与并发

派工时提供以下信息，不假设接收者继承完整上下文：

```text
目标与验收标准：
仓库、基线和当前改动：
负责文件、权限与禁止事项：
适用规则和必读章节：
依赖、预期回传与停止条件：
```

- 计划者明确方案和依赖，实现者修改指定范围，审查者核对实际 diff；角色不固定模型。
- 有依赖的实现与审查顺序执行；独立调查或不同文件的实现可以并行。公共文件需要变更时交回负责人协调。
- 返回结论、改动文件、验证结果及遗留问题；同一会话的小任务直接回传，不另建记录。
- 跨工具的大型写入任务可使用独立分支或 worktree，由主 Agent 整合提交或 patch。工具能力不足时按[能力缺口处理](../reference/agent-runtime.md#工具能力)。

## 交接与恢复

跨会话、跨机器或跨工具接手时，留下可传递记录：

```text
目标、验收标准与负责范围：
分支、基线、HEAD、未提交差异及归属：
已完成、未完成与关键决定：
验证命令、退出码、结果及对应版本：
下一步、环境限制与审查缺口：
```

有代码改动时附提交或 patch，不依赖另一台机器拿不到的临时文件。接手者先核对版本与差异，再决定已有结论是否适用；相同 HEAD 不代表未提交内容相同。交接提供背景，不扩大当前授权，也不要求重复索取已有授权。

## 审查与验证

1. 开始前记录目标分支、基线、HEAD 和未提交差异；审查从该版本的 diff、受影响调用方和验证结果进入。
2. 审查者给出 `APPROVED` 或带文件位置、触发条件和证据的 `CHANGES REQUIRED`。顺序调用另一位审查者也可以形成独立审查。
3. 主 Agent 整合修改后，按[测试与验证](testing-and-validation.md)完成适用检查。记录命令、退出码和所测版本；后续修改只使受影响的证据失效，补验相关部分。
4. 交付时保留未完成审查、未运行检查及失败原因；区分代码问题、已有失败和环境限制。
