# Agent 能力与工具

项目定义任务所需能力，具体模型和调用方式由各 Agent 的实际运行环境决定。

## 能力等级

| 等级 | 适用任务 |
| --- | --- |
| T1 | 定向读取、机械修改、格式整理、运行已有检查 |
| T2 | 默认工程任务：普通实现、测试、修复和重构 |
| T3 | 根因不明、复杂状态流、并发、跨层契约等深推理 |
| T4 | 基础假设可能错误、多方案深度取舍、多次有证据的尝试仍无法解释问题等异常复杂推理 |

选择能可靠完成任务的最低等级，可直接从预计需要的等级开始。风险决定验证强度，不等于推理难度；文件量、耗时和测试数量不自动触发升级。遇到推理瓶颈时记录卡点再升级，关键判断完成后交回适合的等级执行。

## 工具能力

只在使用新能力、环境变化或出现故障时核实相关工具；已确认且未变化的结果复用。

- 使用当前环境提供的工具、模型标识和接口；配置存在、工具宣告支持、实际执行成功是不同证据，不能互相替代。无法确认的能力或模型写“未知”，不猜配置格式。
- 模型不可选时使用当前模型处理能力范围内的工作；可选时再按[能力等级](#能力等级)选择，不假称已切换模型。
- 无子 Agent 或不支持并发时顺序完成可做部分；所需独立审查仍是未完成项，不能以自查替代。
- 启动失败、权限或依赖不足时处理对应环境问题，继续不受影响的工作；不靠升级模型绕过限制，也不把环境失败当成代码缺陷。

## 接入检查

仅首次接入新 Agent、升级后或出现规则加载异常时执行，不是日常开工步骤。未自动加载根规则时，可用[贡献指南中的入口](../../CONTRIBUTING.md#agent-协作入口)。

```text
在 <repo-root> 做只读检查：从 AGENTS.md 判断“跨工具接手”和“模型不可选”分别应读哪些章节，并实际读取。报告所读路径、触发理由和缺失项。不要修改文件、运行测试或启动子 Agent。
```

显式读取成功不证明自动加载生效；自动加载、模型切换和并发支持分别以对应运行证据确认。检查结果留在本次任务记录，不把本机配置快照写入共享规则。
