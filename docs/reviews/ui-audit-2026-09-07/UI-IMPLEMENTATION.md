# AgentHub UI 详细改进方案

状态：建议方案，尚未应用到产品。根据 2026-09-07 的真实桌面审查编写；[审查截图与问题依据](README.md)。本文将配色、层级和布局细化为实现与验收规则，后续页面改动以真实 Tauri 截图复验。

## 1. 设计方向与现有约定

目标是安静、清楚、操作明确的桌面管理工具。保留现有主色、页面底色和主题自定义能力；灰白页面与紫色主操作仅作为默认示例。不引入渐变大背景、彩色卡片墙、额外图标库或新的导航体系。

现行规则见 [设计系统](../../ui/design-system.md)。当前实现统一使用 `src/styles/tokens.ts`，正文/标题/辅助文字仅三档，按钮只有 28px 和 32px 两档，圆角为 6/8/12px。本文沿用这些角色与组件。

本方案包含几项对现有约定的调整建议：正文从 13px 改成 14px、增加成对的状态文字/背景颜色、主色增加前景与交互状态、窄内容区编辑时切换布局。它们不是已生效规范。实施时应一起更新设计系统、共享样式和相关测试，不在单页写一套临时数值。现有主题、主色和底色偏好继续保留，不重置用户选择。

### 必须保留的颜色设置

现有设置是方案的输入，不能被新版样式覆盖：

| 设置 | 当前可选项 | 改进后的要求 |
|---|---|---|
| 主题 | 浅色、深色、跟随系统 | 三项全部保留；跟随系统时主题自动更新，用户选择的主色和底色不丢失 |
| 主色 | 紫色、蓝色、青色、玫红、橙色 | 五项全部保留；主按钮、链接、开关、焦点和相关淡底一起变化 |
| 页面底色 | 浅灰、浅白、纸色、雾色、天蓝、薄荷、沙色、淡紫 | 八项全部保留；只作用于浅色主题，深色时保留所选值供切回恢复 |

**不能把“统一配色”实现成“固定紫色和灰底”。统一的是角色与质量，不是用户选择。**页面代码只使用共享样式变量，不读取颜色名称来写特殊分支。状态色和 Agent 品牌色不随主色改变：例如用户选择青色主色后，普通青色按钮仍不代表操作成功。

### 本轮重点解决什么

| 现在 | 改后应当怎样 |
|---|---|
| 标题、版本、正文、状态挤在相近的字号和灰度里 | 先看到页面和对象，再看到状态与主操作，最后看到时间和技术详情 |
| 多个按钮、徽标和图标争夺注意力 | 同时只突出一个页面主动作，行内动作保持次级 |
| 配色只定义一个绿色/橙色，文字和底色混用 | 状态文字、状态底色、图标分别有明确角色 |
| 列表很空，名称和表单却被截断 | 宽度先给名称和必填项，低频信息进入详情 |
| 不同页面对错误、空值、等待的表达不一致 | 就地说明状态，给出下一步，同时保留正常内容 |

## 2. 配色：使用明确的角色

### 2.1 中性色与背景

基础面保持中性，让 Agent 标志、状态和主操作自然突出。以下为建议值；“保留”意味着不必为了改进而换色。

| 用途 | 浅色 | 深色 | 使用方法 |
|---|---|---|---|
| 页面底色 `bg-canvas` | `#F3F3F5`，保留 | `#0A0A0B`，保留 | 页面与容器之间的空隙，禁止承载低对比度浅字 |
| 内容面 `bg-panel` | `#FFFFFF`，保留 | `#121214`，保留 | 表格主体、表单、侧栏、弹窗 |
| 次级条带 `bg-subtle` | `#ECECEF`，保留 | `#1A1A1D`，保留 | 表头、分段筛选轨道、小段只读内容；不要整页反复铺灰块 |
| 悬停背景 `bg-hover` | `#EBEBED`，保留 | `#1E1E22`，保留 | 可操作行/按钮的 hover |
| 选中背景 `bg-active` | `#E4E4E7`，保留 | `#2C2C31`，保留 | 当前页、当前详情对象；不要把整条表格行染紫 |
| 主要文字 `text-primary` | `#18181B`，保留 | `#FAFAFA`，保留 | 标题、名称、关键数字、字段值 |
| 次级文字 `text-secondary` | `#55555D`，保留 | `#A1A1AA`，保留 | 普通说明、字段标签、表头 |
| 辅助文字 `text-muted` | **`#62626C`** | `#A1A1AA` | 时间、路径摘要、补充说明；比原浅色 `#70707A` 更深 |
| 禁用文字 `text-disabled` | `#A1A1AA`，保留 | `#71717A` | 仅确实不可操作的内容；不能用来表达未知、为空或未登录 |
| 装饰分隔线 `border` | `#E6E6E9`，保留 | `#27272A`，保留 | 卡片边界、表格分隔；不承担识别输入框的唯一作用 |
| 控件边界，建议新增 `border-control` | `#85858F` | `#71717A` | 输入框、选择框、未选复选框等必要轮廓；不要套给每张卡片 |

使用边界：建议的浅色 `text-muted` 为 `#62626C`，对默认画布约 5.44:1、默认次级条带约 5.11:1、选中灰底约 4.75:1；对沙色和淡紫的次级条带分别约 4.87:1、4.92:1。初稿候选 `#686872` 在沙色与淡紫条带上分别只有约 4.45:1、4.49:1，因此已放弃该候选，不能只按默认灰底配色。选中行的重要内容仍用主要/次级文字。未知值“尚未获取”保持可读，不淡化成禁用状态。

输入框边界相对当前浅边框会更明显，这是让可编辑区域可辨认的有意调整。保持 1px，聚焦才增加焦点环，避免所有容器一起变成重边框。

### 2.2 主色：默认紫色及完整交互状态

紫色用于“我可以在这里操作”和“我现在选中了什么”，不表示成功、失效或 Agent 类型。

| 角色 | 默认浅色方案 | 默认深色方案 | 用途 |
|---|---|---|---|
| 主按钮填充 `accent` | `#4F46E5` | `#A5B4FC` | 页面唯一主动作、选中的开关 |
| 主按钮文字 `accent-foreground` | `#FFFFFF` | `#1E1B4B` | 深色主题使用浅紫底配深字，不继续固定白字 |
| 悬停 `accent-hover` | `#4338CA` | `#C7D2FE` | 清楚但不跳动的 hover |
| 按下 `accent-pressed` | `#3730A3` | `#818CF8` | 保留同一色相，无缩放或弹跳 |
| 主色淡底 `accent-subtle` | `#EEF2FF` | `#252343` | 局部选项提示、焦点附近的轻强调；不取代灰色表格选中态 |
| 主色文字 `accent-text` | `#4338CA` | `#C7D2FE` | 链接、可操作文字，与填充按钮角色分开 |
| 焦点 `focus-ring` | `#4F46E5` | `#A5B4FC` | 键盘聚焦：2px 实色环，2px 与组件背景的间隔 |

不要在 hover 时仅将整个按钮透明度降低：透明度会与不同背景混色，文字对比度不稳定。建议改用上述明确状态色。

保留蓝、青、玫红、橙色选项，但 `ACCENT_PALETTES` 需从仅有 light/dark 的单色扩展为填充、前景、悬停、按下、淡底和链接色的成组配置。以上紫色值只是一组默认值，业务页必须引用语义颜色。其他主色可沿用现有色相，但每组都应测量前景/背景组合；不要给深色青色底机械套白字，也不要在用户选蓝色后留下紫色焦点或选中提示。

颜色配置放在 `tokens.ts`，由当前生成方式输出 CSS 变量；同步调整 `tailwind.config.ts` 与 accent 覆盖生成逻辑。不要在页面上散写 HEX。

焦点环使用各组填充色，并以 panel 背景留出 2px 间隔。深色按钮的文字不是固定白色，应取该组前景色。本次计算五组深色按钮在默认/悬停/按下三个状态的最低文字对比度分别约 5.36、5.78、7.77、5.81、6.92:1；仍需检查实际 CSS 透明度与渲染。

### 2.2.2 页面底色与主色独立组合

保持 `CANVAS_PALETTES` 的现有色值，不因调整主色强制切换底色：

| 底色选择 | 页面 / 次级条带 |
|---|---|
| 浅灰 | `#F3F3F5` / `#ECECEF` |
| 浅白 | `#FAFAFA` / `#F0F0F0` |
| 纸色 | `#F6F3EE` / `#EEE8E0` |
| 雾色 | `#EEF2F6` / `#E4EAF0` |
| 天蓝 | `#EEF5FB` / `#E3EEF8` |
| 薄荷 | `#EEF8F3` / `#E1F0E8` |
| 沙色 | `#F6F0E6` / `#EEE6D8` |
| 淡紫 | `#F4F1F8` / `#EBE6F2` |

内容面浅色仍为白色，先通过统一面板保证表单与正文可读；底色主要出现在页面空隙和次级条带。不要把所有卡片也染成用户底色。五主色 × 八底色的 40 种浅色组合都应做计算检查；截图至少抽取默认、橙色＋沙色、紫色＋淡紫、青色＋薄荷以及边界组合，再逐项覆盖其他组合的可读性。

主题切换规则：选蓝色和纸色后切深色，应呈现蓝色深色方案及深色画布；再切浅色，应恢复蓝色和纸色。跟随系统走相同规则。样式生成时必须确保浅色底色覆盖规则不会因为 CSS 优先级压过深色主题，不能仅依靠注释约定“只影响浅色”。

### 2.3 状态色：文字与背景成对配置

状态用颜色加文字，必要时加图标。徽标建议高 24px、水平内边距 8px、12px 文字；长状态允许换行到独立说明，不压缩至不可读。

| 状态 | 浅色文字 / 背景 | 深色文字 / 背景 | 文案例子与使用边界 |
|---|---|---|---|
| 成功 | `#15803D` / `#F0FDF4` | `#86EFAC` / `#142A20` | “安装完成”“检测通过”；仅有配置文件不能推导检测通过 |
| 需处理 | `#92400E` / `#FFFBEB` | `#FCD34D` / `#302510` | “需重新登录”“即将用尽”，旁边给具体动作 |
| 失败 | `#B91C1C` / `#FEF2F2` | `#FCA5A5` / `#321B22` | “连接失败”“保存失败”；不要整条列表铺大面积红色 |
| 信息 | `#1D4ED8` / `#EFF6FF` | `#93C5FD` / `#17263B` | “只读”“检测中”的补充说明 |
| 中性 | `#55555D` / `#ECECEF` | `#D4D4D8` / `#27272A` | “未配置”“尚未获取”“已隐藏”，不把正常空状态标为错误 |

“使用中”表示当前选择，可以用主色文字配淡底；“已配置”表示事实，用中性文字。两者都不等于“请求已验证成功”。连接状态与当前选择最好分开显示，避免用一个绿点同时表达三件事。

危险确认按钮另用成对配置：浅色底 `#B91C1C` 配白字；深色底 `#FCA5A5` 配 `#450A0A`。列表里的删除入口仍是低强调文字或更多菜单项，只有最终确认按钮用实色危险样式。

### 2.4 Agent 颜色与图表颜色

- 保留真实 Agent 标志及品牌颜色，主要出现在 16–20px 图标、名称旁和图例中，不铺满卡片，也不承担登录是否正常的含义。
- 本次总览里 Grok、Pi 都是近黑色。图表继续保留品牌色时，一条实线、一条虚线，并在图例同时展示线型与文字；悬停和键盘能查看具体数值。不能只靠黑色圆点区分。
- 折线建议 2px，面积填充透明度 8%–12%，网格使用装饰分隔线；填充越多越遮挡其他系列，不要每条线都做深色渐变面积。
- 图表旁直接写“含输入、输出和缓存”，日期范围由共同筛选决定。空数据改为简洁说明，不画容易误认为真实观测值的装饰波形。
- 有很多 Agent 时，图例允许换行或滚动并保留名称；“其他”若用于聚合，必须能展开查看，不能隐藏总数构成。

### 2.5 对比度计算与限制

下表由 HEX 相对亮度公式计算，是本方案色值检查，不是实际渲染、半透明背景、所有用户主题或全应用的通过证明。

本次文档校验已计算 30 组主按钮前景/状态底色、40 种浅色主色与页面底色组合中的链接/焦点/辅助文字，以及 8 种次级条带上的辅助文字。上述指定组合达到本方案相应计算目标，主按钮最低约 4.70:1；不包括所有任意叠加、透明状态、图表或实际渲染结果。实施后的验收清单仍需执行。

| 前景 / 背景 | 比值约值 |
|---|---:|
| 浅色主按钮：`#FFFFFF` / `#4F46E5` | 6.29:1 |
| 深色主按钮：`#1E1B4B` / `#A5B4FC` | 8.02:1 |
| 深色主按钮按下：`#1E1B4B` / `#818CF8` | 5.36:1 |
| 浅色辅助文字：`#62626C` / `#F3F3F5` | 5.44:1 |
| 浅色成功文字 / 对应状态底色 | 4.79:1 |
| 浅色警告文字 / 对应状态底色 | 6.84:1 |
| 浅色失败文字 / 对应状态底色 | 5.91:1 |
| 浅色信息文字 / 对应状态底色 | 6.16:1 |
| 深色成功 / 警告 / 失败 / 信息文字，对各自底色 | 10.82 / 10.42 / 8.41 / 8.46:1 |
| 浅色控件边界 / 白色内容面 | 3.65:1 |
| 深色控件边界 / 深色内容面 | 3.87:1 |

普通有效文字以至少 4.5:1 为验收目标；必要控件视觉边界另行检查，不把装饰分隔线和禁用控件混为同一要求。参照 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。有色页面底色必须逐一验证，不用默认灰底的结果替代。

## 3. 层级：分别定义内容、视觉和操作

### 3.1 内容层级：每种信息有固定位置

| 层级 | 用户需要知道什么 | 摆放位置 | 举例 |
|---|---|---|---|
| 第一级：当前任务 | 这是哪一页，我能做什么 | 页头：标题左，唯一主动作右 | “连接” / “添加登录” |
| 第二级：当前对象与状态 | 正在看哪个 Agent、登录或会话，有没有事要处理 | 名称、状态列、表单顶部或输入区附近 | 登录名称、“需重新登录”、当前项目 |
| 第三级：完成操作需要的内容 | 怎么筛选、该填什么、会得到什么 | 筛选栏、带标签字段、行内明确动作 | API Key、服务地址、继续对话 |
| 第四级：补充说明 | 时间、用量口径、更新提示 | 次级一行、字段下说明、图表副标题 | “总 Token 含缓存”“3 分钟前更新” |
| 第五级：技术详情 | 文件路径、完整标识、原始配置 | 详情区、折叠高级设置、复制操作 | 配置文件路径、会话标识 |

关系到正确选择的说明不能藏在问号里，例如“已用”还是“剩余”、添加后写到哪里、为什么无法继续。只有低频解释放悬停提示。用户不需要先读帮助才能理解列名。

### 3.2 字体层级：仍然只用三档

| 用途 | 字号 / 行高 | 字重 | 颜色 |
|---|---|---|---|
| 页面标题、弹窗标题、关键指标 | 16px / 24px | 600 | 主要文字 |
| 分区标题 | 14px / 22px | 600 | 主要文字 |
| 列表名称、表单字段值、正文 | 14px / 22px | 400；重要名称可 500 | 主要文字 |
| 字段标签、按钮 | 14px / 22px | 500 | 标签用次级文字，按钮按角色 |
| 时间、路径摘要、版本、表头 | 12px / 18px | 400；表头可 500 | 次级或辅助文字 |
| 必须理解的状态、错误原因 | 优先 14px / 22px | 400–500 | 对应状态文字色；不要因属于说明就降至 12px |

本轮不新增 20/24/32px 的大标题体系。指标仍为 16px，但放在独立区域、使用 600 字重并弱化标签，不再通过大卡片和空白“撑出”重要性。标题与正文的差异还要靠位置、间距与容器实现。

中文继续使用现有系统字体；等宽字体只用于路径、代码与必要标识。用量、时间和版本使用等宽数字特性方便纵向比较，不把整段中文说明换成等宽字体。不要靠降低整个行容器 opacity 来弱化辅助信息。

### 3.3 表面层级：最多三层，不反复套卡片

1. 页面底：`bg-canvas`，无阴影。
2. 工作内容：`bg-panel` 加 1px 装饰边界；列表只需要一个外壳，内部用行分隔。分区之间用空隙，不再每行套一张卡片。
3. 临时浮层：菜单使用现有 `shadow-md`；模态弹窗使用 `shadow-lg`，遮罩浅色用黑色约 40%、深色约 60%，以真实画面调整。侧边详情是并排内容面，不需要和模态弹窗同样重的阴影。

菜单、下拉框必须显示在弹窗上方；弹窗打开时焦点留在弹窗中。优先继续使用现有 Radix 的层级管理，不在各页面任意增加超大 z-index。

### 3.4 操作层级：按钮看起来就应当有主次

| 操作 | 样式与尺寸 | 原则 |
|---|---|---|
| 页面主动作 | 主色填充，32px 高，水平 16px 内边距 | 同时只突出一个，例如添加登录 |
| 表格行主动作 | `secondary`，28px 高，图标加文字 | 例如继续对话、安装；重复行不出现一列紫色按钮 |
| 取消、刷新等辅助操作 | `secondary` 或工具栏既有规范 | 不与主动作争夺注意力；PageRefreshButton 保持共享样式 |
| 打开目录、帮助、更多 | `ghost`，28px 方形目标 | 16px 图标，必须有名称与悬停说明 |
| 关闭、清空 | 28px 方形目标，视觉图标 16px | 扩大点击区，不放大 X 图标本身 |
| 删除入口 | 更多菜单项或低强调危险样式 | 不在日常列表反复铺红色按钮 |
| 删除最终确认 | 实色危险按钮 | 显示具体对象与后果；沿用已有确认规则 |

侧边添加表单打开时，“添加 API Key”成为主动作；背景列表的“添加登录”降为次要或暂时隐藏，避免两个主动作。空状态提供主按钮后，页头同名按钮也降级或隐藏。查看详情不等于进入编辑，两者不能混用保存按钮。

## 4. 尺寸、留白和布局规则

### 4.1 间距与控件

| 项目 | 建议值 | 落地说明 |
|---|---|---|
| 应用外边距 | 8px，保留 | 保留桌面窗口边缘结构 |
| 表格/工作区内侧边距 | 12px | 建议由共享 `pageEdge.inset` 从 8px 调至 12px；不在各页分别加 padding |
| 页头高度 | 最小 48px，可随长标题换行增高 | 标题与操作垂直居中，不能固定高度裁切 |
| 筛选栏与主体间距 | 16px | 分隔“怎么筛选”和“结果是什么” |
| 同组控件间距 | 8px | 搜索、筛选、次要动作 |
| 分区间距 | 24px | 例如指标与图表、设置分组 |
| 表单字段间距 | 16px | 标签与输入 4px，输入与说明 4px |
| 内容面内边距 | 普通 16px，弹窗 24px | 密集表格由单元格 padding 控制，不叠加两次 |
| 单行列表 | 最小 44px | 多行内容增长，不用固定高度隐藏文字 |
| 两行名称列表 | 最小 56px | 名称第一行、来源或时间第二行 |
| 表头 | 最小 36px | 12px 表头用次级文字，不做极淡灰 |
| 输入框 | 表单 32px，紧凑工具栏 28px | 通过共享 size 支持；不要单页随意写高度 |
| 圆角 | 控件 6px、面板 8px、对话输入 12px | 沿用现有角色，不统一改成大圆角 |

正文 14px 与控件高度需一起回归：不要只增大字号，导致文字上下紧贴边线。桌面操作不必机械把所有按钮改到 44px，但需要检查密集操作间距和命中能力。

### 4.2 宽度：按内容区剩余宽度判断

仍保留现有两种内容系统：表格、列表与工作区使用边缘布局；设置和长对话使用现有居中阅读列。不要每页另起一个 max-width。

- 一级侧栏保持现有宽度与可调行为；用户手动调整优先，不反复强制重置。
- **内容区至少 960px：**允许并排详情，示例为左侧 440px + 中间 16px + 右侧 504px。左侧改为简化列表，不能继续保留所有表格列。
- **内容区不足 960px：**编辑面板占满当前内容区，顶部提供“返回连接”；保留搜索、筛选、滚动位置和选中对象，返回后恢复。
- **关闭详情：**恢复完整表格。名称优先扩展；时间可用“几分钟前”，精确时间放详情或提示。
- 筛选栏空间不足时换行：第一行搜索和主动作，第二行 Agent 与其他筛选。不缩小字号来硬塞。
- 长名称优先换两行；确需截断时支持鼠标和键盘查看完整文本。表单错误、金额/额度语义与主操作不可截断。

960px 指扣除侧栏、间隔与内边距后的可用内容宽度，不是整个窗口宽度。实现时用容器宽度判断或等效布局测量，并验证断点附近没有来回切换。未来若保存自定义列宽，简化详情列表使用独立布局，不覆盖用户完整表格的列宽偏好。

## 5. 页面级具体改法

### 5.1 总览：状态优先，数字口径紧跟数值

参考 [原页面](screenshots/03-real-overview.jpg)。从上到下按以下顺序：

1. 页头：总览；右侧保留帮助、通知等低强调入口。就绪数明确描述究竟是“已安装”还是“可开始对话”，不混为一个数字。
2. Agent 状态区：标志与名称第一行，当前登录与状态第二行。已配置用中性，需处理用警告文字并给“管理连接”。不要仅保留绿色/灰色圆点。
3. 共享筛选栏：时间范围、Agent、模型；右侧“采集”与“上次同步时间”。自动同步倒计时降为辅助信息，不压缩筛选。
4. 指标一排：输入（不含缓存）、输出、缓存、估算成本。缓存数据需使用已有真实统计能力，不能新增一个假值；暂时拿不到时不显示该指标，仍明确图表口径。
5. 趋势：标题“总 Token（含缓存）”，副标题给当前范围与真实总数。曲线区建议约 240–280px 高，减少高图表把其他信息推到很远的位置。
6. 分布与明细：分布保留总数和单位，明细保留详细列；价格缺失说明同时出现在成本附近，避免只在页尾提示。

异常时只标记受影响 Agent 或统计区，仍显示其他可用数据。没有记录时显示“尚无用量记录”和采集说明，不等同于用量确认为零。

### 5.2 连接：先认人，再看状态，最后操作

参考 [原页面](screenshots/04-real-connections.jpg)。建议完整表格列顺序为：

| 列 | 宽度建议 | 呈现 |
|---|---|---|
| 登录 | 剩余空间优先，建议至少 220px | 名称 14px；Agent 与官方登录/API Key 类型作为第二行或独立紧凑标识 |
| 状态 | 120px 起 | 已配置、需重新登录、未知等事实状态；当前使用另用“使用中”标识 |
| 用量 | 180px 起 | “7 天已用 80%”和进度；Token 型说明输入、输出；缺失写尚未获取 |
| 最近使用 | 120px 起 | 相对时间；完整时间可查看 |
| 操作 | 112px 起 | 行主动作与更多；不能让主动作藏在水平滚动之外 |

Agent 与类型若移入名称第二行，其筛选仍保留，不能减少识别能力。列宽为建议下限，容器不足时切简化布局，不叠加成无限增长的表格。

额度：0% 有“已用 0%”文字，不能只画一条灰轨道；100% 写“已用 100%”，必要时提示额度用尽。刷新失败显示更新时间与失败提示，保留旧值并说明，不能归零。

添加入口统一使用用户术语，例如“添加登录”，菜单中明确官方登录与 API Key。这是文案建议，实施时一并更新翻译与相关帮助，不改内部 API 名。

### 5.3 添加 API Key：表单按用户填写顺序排列

参考 [原页面](screenshots/05-real-add-api-key.jpg)。右侧或单列编辑区建议依次为：

1. 标题“添加 API Key — Codex”，下方一行明确保存范围；具体文字根据当前实际写入行为确定。
2. 服务选择：官方服务 / 自定义服务。
3. API Key：常驻标签、遮挡输入、可访问的显示按钮。不要自动展示原有完整 Key。
4. 自定义服务时才显示服务地址，必要时显示模型；官方模式不占空间展示一长串禁用字段。
5. 名称（可选）：用于辨识，给简洁示例。
6. “粘贴配置自动填入”：折叠便捷区，打开后提供粘贴和识别。解析失败只标记此区；不得覆盖已经输入的内容。
7. “高级设置”：折叠模型细项、接口格式和只读配置预览；本机文件位置也在这里。
8. 底部固定操作栏：取消 + 添加 API Key。内容滚动，按钮不随表单滚出视野；不再顶部和底部各放一套主按钮。

字段错误紧接字段下方，使用错误文字及说明关联。提交时保留按钮宽度，显示“正在添加”；沿用当前正在写入时的退出限制。成功与读取刷新失败区分：“已添加，但列表刷新失败”，不能提示用户再次添加造成重复。

### 5.4 对话：集中开始条件，减少重复标题

参考 [新对话](screenshots/07-real-new-chat.jpg)。

- 空状态标题仍用 16px，下面直接列“Agent：Pi”“项目：AgentHub”，项目可修改。缺少项目时主动作是选择目录，缺少连接时是添加或选择连接。
- 页面底部保留 Agent、连接、模型和思考强度控件，属于熟练用户操作区。不可用时说明具体原因，不把整排控件淡化却不给解释。
- 历史项使用两行：标题 / Agent · 项目 · 时间；内容过长时优先保留标题前部，完整标题可查看。颜色点不再独自承担 Agent 身份。
- 新建但未发送的对话标为草稿。是否不保存空草稿属于行为变更，需单独验证恢复流程，不能在本轮直接清理已有记录。
- 对话区域沿用阅读列；消息正文与代码块可读性分别测试，不借 UI 字号调整直接改坏 Markdown 排版。
- 输入区初始高度约 120–160px，保留现有拖动；生成中停止、失败重试、等待确认要有明确文字或辅助阅读名称。

### 5.5 Agent：状态不混用，安装动作看得见

参考 [原页面](screenshots/09-real-agents.jpg)。

- 运行环境全部正常时，默认显示简洁摘要“运行环境已就绪”和展开检查入口；存在缺失时展开对应问题及修复动作。不要把正常状态也做成需要用户马上处理的告警。
- “已安装”与“已隐藏”分开表达：安装是软件状态，隐藏是界面偏好。已隐藏行可弱化背景，但保留足够可读的名称和取消隐藏动作。
- 未安装行显示文字“安装”；已安装行保留启动。更新有新版本时显示“更新”，无更新时用“已是最新”；强制升级放更多菜单。
- 表格“说明”若大部分为空，可移至详情，释放宽度给 Agent 名称与操作。
- 长名称可以两行，图标不压缩；版本使用辅助文字。

### 5.6 技能与 MCP：空状态和表单一致

参考 [技能安装](screenshots/11-real-skill-install.jpg)、[MCP](screenshots/13-real-mcp.jpg)。

- 空共享库显示标题“还没有技能”、一行说明、主按钮“安装技能”，另有次要入口“技能市场”。所有为 0 的状态过滤可暂时收起，添加首个技能后出现。
- 安装对话框提供来源选择：本地目录、zip 文件、Git 地址。前两者提供系统选择器；Git 为带常驻标签的输入框。选好后显示名称与可查看的完整路径。
- 在按钮前明确“安装到共享库，不会自动启用”。本轮不把安装与启用合并，避免改变现有行为。
- 空值/格式错误用字段内提示；真正开始安装后用阶段信息，失败保留来源以便重试。
- MCP 保持只读说明。路径用等宽辅助文字，但不要占满名称的宽度；详情展开显示完整命令。无记录时只说明未发现，不增加假的安装入口。

### 5.7 项目：搜索结果直接对应会话

参考 [会话列表](screenshots/15-real-project-sessions.jpg)和[搜索](screenshots/16-real-project-search.jpg)。

- 项目头：项目名、Agent、会话数；路径放第二行或可展开辅助信息。
- 会话行：左侧标题占剩余宽度，中间保留最近时间，右侧“继续对话”和更多。文件名、标识、体积进详情，不与标题争空间。
- 搜索时自动展开命中组，在项目名后显示“1 条匹配”，只对命中词做轻强调，不给整段结果铺主色底。
- 清空查询恢复查询前的展开状态；搜索过程中用户手动展开/折叠也应有明确规则，不能不断自动抢回。
- 区分“没有匹配”和“尚未搜索未加载会话”。如果跨未加载会话搜索需要新增加载逻辑，作为独立功能实现；本轮仅靠 CSS 不能解决。
- 删除放更多菜单，沿用真实删除/恢复能力说明，不改变数据保留规则。

### 5.8 路由：区分健康的未使用与需要配置

参考 [看板](screenshots/18-real-routes.jpg)和[连接池](screenshots/19-real-route-pool.jpg)。

- 健康的关闭状态不是错误。顶部显示“本机转发已关闭”，不要渲染红色告警或暗示所有用户都必须启用。
- 用户进入空连接池时，主动作“从连接同步”，次要动作添加 API Key、官方登录；同步候选只展示现有规则支持项，不能暗示所有官方登录可共享。
- 用户希望开始使用路由时，提供简短的三步引导：添加可用连接、创建入口 Key、开启本机转发。根据真实状态显示已完成项，不制作只会变化外观的假步骤。
- 从未使用的看板用“尚无本机转发记录”替代大面积零曲线。已有历史但当前关闭时，历史仍可查看，不能因关闭清空图表。
- 端点地址、协议和技术信息折入详情，默认强调用途和运行状态；复制地址等技术操作继续可达。

### 5.9 设置：同一行应当是一个完整可理解的选择

参考 [原页面](screenshots/20-real-settings.jpg)。

- 保留偏好、本机、备份、关于分组与现有阅读列。
- 每行左侧标签 14px，下方说明 12px；右侧控件。长标签允许换行，窄空间时控件放下一行，不与说明相撞。
- 标签、说明、控件用 id/aria-labelledby/aria-describedby 或等效语义关联。点击可关联标签能够操作控件，不给整组容器不加区分地增加点击行为。
- 主色样本在原有 radio 语义基础上保留选中环和名称；页面底色样本同样提供名称。不能只靠两个相近色块判断选中状态。
- 立即保存沿用现有逻辑，失败需要显示未保存并恢复可信状态；不要只在视觉上保持开关已变更。
- 路由侧栏折叠行为先在文案中说明；若决定退出时恢复，单独测试与手动调整的优先级。

## 6. 交互状态统一规则

| 状态 | 显示什么 | 不应发生什么 |
|---|---|---|
| 默认 | 清晰标签、当前值、可操作边界 | 通过极低透明度让可操作控件看起来被禁用 |
| 悬停 | 背景或边线轻变，不改变尺寸 | 放大按钮、新增阴影造成布局跳动 |
| 键盘聚焦 | 可见实色焦点环；滚动区域让目标进入视野 | 只修改颜色而无清楚焦点，焦点被固定操作栏遮住 |
| 选中 | 稳定灰色底、文字/选中标记，表格批选另用复选框 | 把批选、查看详情、当前登录合为一种状态 |
| 禁用 | 真实 disabled，加可获取的原因 | 用透明度制造假禁用，仍然触发操作 |
| 正在处理 | 保留原内容和按钮宽度，给阶段文字 | 点击后全页清空、重复请求、永久旋转没有恢复入口 |
| 成功 | 简短结果提示；需要后续操作时给明确入口 | 每次成功弹模态窗打断用户 |
| 错误 | 字段错误靠字段；整块失败靠整块；可重试 | 只发瞬间 toast、丢输入、把已有记录变成零 |
| 未知 / 无数据 | 明确“尚未获取”或“暂无记录” | 当成失败或者伪造成功状态 |

普通颜色变化建议 120–150ms；面板展开约 150–180ms。不使用弹簧或回弹。系统减少动效时取消宽度、位移、缩放动画，必要状态改用文字表达；颜色过渡也可直接切换。此处是建议，尚未完成系统偏好真机验证。

## 7. 实施拆分与代码落点

| 顺序 | 工作 | 主要落点 | 完成条件 |
